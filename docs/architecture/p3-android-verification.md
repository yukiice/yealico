## 2. 真机才暴露的两个问题

### 2.1 error 横幅吞掉了已解析的列表（已修）

阿巴基猫声明了 `searchUrl`，`buildRoutePlan` 因此产生：

```text
ERROR UNSUPPORTED_FEATURE @ searchUrl — search is not implemented in v1
```

`SiteWorkspace` 原来把「有没有 error 级诊断」当成「能不能展示内容」，于是：

- 调试页显示 `items=70`，说明 70 条已经解析出来；
- 界面却只有一行错误，列表完全不渲染。

引擎里真正阻断执行的只有 `NEEDS_WEBVIEW / NEEDS_LOGIN / NEEDS_CONSENT`（`blockingDiagnostics`），`UNSUPPORTED_FEATURE` 只是提示。修复方式是把判断改成“有内容就展示内容、诊断只做横幅”，落在 `src/app/presentation.ts` 的 `contentState`，`SiteWorkspace` / `DetailScreen` 共用。

### 2.2 阅读器报错把图床签名直接上屏（已修）

漫画柜章节页 WebView 超时后，诊断详情里带了真实图片地址：

```text
https://eu1.hamreus.com/.../2099_ALPHA_0.jpg.webp?e=1793771509&m=somwbCWkrsmGioLKBdzZAw
```

原来只有调试页调用脱敏，`errorText`（列表/详情/阅读器的横幅）是原样拼接。修复：

- `errorText` 统一过 `sanitizeText`；
- `sanitizeText` 兼容真实诊断的两种脏形态：HTML 转义的 `&amp;` 分隔符、`|` 拼接的候选值；
- 增加“值形态”识别：长度 ≥ 20 且大小写混合的参数值按签名处理（`m=...` 这种名字看不出问题的参数也能遮住）。

## 3. 已修复：漫画柜章节选择器漂移

首次验收时阅读器报：

```text
NETWORK_ERROR: WebView render timed out after 15000ms … wait=#manga>img … imgs=2
```

页面里确实有图（`imgs=2`），但 `wait` 用的是旧布局的 `#manga>img`，现行章节页把图片放在 `#mangaBox img.mangaFile`。

修法不写死在代码里，而是改规则源文件 `artifacts/yealico-rules/site-6-*.json` 的 `gallery.image.selector`，用逗号分组兼容两种布局：

```json
"selector": "#mangaBox img.mangaFile, #manga>img"
```

然后 `npm run rules:sync` 重新生成 `real-rules.generated.ts`。设备上「漫画柜在线探针」复验：`images=1, errors=none`，阅读器也能出图（当时总页数仍是 unknown，见第 4 节）。

## 4. 已修复：分页总数改从 `#pageSelect` 读取

总页数原来读 `span.manga-page`（已不存在）。先用探针把真实 DOM 打出来：

```text
img=1 | mangaBox=1 | mangaFile=1 | legacyImg=0 | mangaPage=0
| select=1 | option=18 | pageLink=0 | pageClass=1
| <select id="pageSelect"><option value="1">…
```

结论：每页 1 张图，页码在 `#pageSelect` 的 option 值里，最后一个 option 的 value 就是总页数。规则改为：

```json
"totalPages": {
  "selector": "#pageSelect option:last-child",
  "function": "attr",
  "param": "value"
}
```

真机复验：探针 `images=1, totalPages=18`；阅读器 `1 / 4 图 · 已载 4 页 / 24` + 「继续加载（4/24 页）」。

## 5. 仍然存在的限制

- **`|||` 拼接、无 `=` 的 token 未脱敏**：例如 `...webp|||sGIEwtLn`。这类值没有参数名可依据，按值形态判断又会误伤 `mangaFile` 这类字段名，暂不处理。

## 6. 开发环境注意
- **没有 Watchman，Metro 监听会漏掉工具写入的改动**：改完源码要重启 Metro，否则模拟器拿到旧 bundle。本次排查中最初 `grep contentState` 为 0 就是这个原因。
- **`adb shell input text` 会把首字母大写**：输入 `http://…` 变成 `Http://…`，RN 的 fetch 直接报 `Network request failed` 且服务端收不到请求。绕过方式：先输入 `xhttp://…`，再 `keyevent 122`（HOME）+ `keyevent 112`（FORWARD_DEL）删掉首字母。
- **`adb reverse` 不一定稳定**：`--list` 里有映射、`toybox nc` 也连不上时，`--remove-all` 后重建即可；定位时优先用 `toybox nc 10.0.2.2 <port>` 验证设备到宿主的链路。
- 真机验证脚本化的前提是坐标稳定；页面文案一变，`adb shell input tap` 的坐标就要重新从 `uiautomator dump` 里取。
