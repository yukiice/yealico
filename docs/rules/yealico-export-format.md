# Yealico 导出 JSON 格式分析

- 样本来源：用户提供的导出内容（单个 JSON 对象）。
- 记录日期：2026-10-20
- 关联：[QR 研究结论](qr-import.md)、[客户端取明文](yealico-rule-extraction.md)、[待确认项](open-questions.md)

## 1. 外层结构

```json
{ "encrypted": "v2:<base64>" }
```

| 项 | 值 |
| --- | --- |
| 外层字段 | `encrypted` |
| 内层前缀 | `v2:` |
| Base64 长度 | 5120 字符 |
| 解码后长度 | **3840 bytes** |
| 是否 16 字节对齐 | 是（240 个 AES 块） |
| 前 16 字节（hex） | `957901d655b3d6935f311ba1f6192a69` |
| 末 16 字节（hex） | `665a9f3516f26c310daf2eabfff39f9e` |
| 字节熵 | 约 7.95 / 8 |
| 可打印字符比例 | 约 38% |

结论：**不是明文规则 JSON，也不是常见压缩数据**。它是 Yealico 的加密导出容器。

## 2. 已排除的编码/压缩

- zlib / gzip / bz2 / lzma：失败。
- Brotli / zstd / raw inflate：失败。
- LZString：返回乱码。
- 直接把 Base64 当 UTF-8 JSON：失败（高熵二进制）。

3840 字节且 16 字节对齐，符合 AES-CBC/GCM 一类分组加密；但也可能是自定义二进制封装，不能仅凭长度断定算法。

## 3. 二维码是否就是导出密钥

假设：二维码里的 64 字节可能是解密导出文件的密钥/种子。

已测试（**前提是这份导出与禁漫天堂大陆版二维码属于同一规则**）：

- QR 字节的不同切片作为 AES-128/192/256 密钥；
- SHA-256 / MD5×2 / hex / Base64 派生；
- PBKDF2（盐为导出前缀、QR 前缀、`Yealico`，迭代 1/1000/10000）；
- AES-CBC / CTR / CFB / OFB / GCM（nonce 12/16）/ ECB；
- 导出前缀、QR 前缀、零 IV；
- 共 986 种组合，没有得到可读 JSON/URL。

**重要限制**：目前不能确认这份导出就是那张禁漫二维码对应的规则。若不是同一规则，这组测试不能说明“QR 不是密钥”，只能说明“这两个样本组合无效”。

## 4. 可能的三种情况

| 情况 | 特征 | 后续 |
| --- | --- | --- |
| 导出用 QR 中的便携密钥加密 | 换设备导入同一 JSON 仍可成功 | 值得继续找 KDF/模式；需要同规则 QR+导出+明文 |
| 导出用账号/设备密钥加密 | 只能本机或同一账号导入 | 跨设备兼容不成立，需明文导出 |
| 导出用静态 App 密钥 | 所有导出同格式，密钥在客户端 | 需要官方格式或授权，默认不逆向 |

## 5. 当前处理

`src/app/ruleImport.ts` 的 `parseRuleJson` 会先看外层：

- 普通规则 JSON → 按 `RuleDocument` / 提取结构导入；
- `{ "encrypted": "v2:..." }` → 错误码 **`UNSUPPORTED_ENCRYPTED_EXPORT`**；
- 不会把加密导出误判成规则，也不会静默返回空站点。

（原 `parseQrPayload` 已随二维码功能删除，导出识别不依赖它。）

测试：`__tests__/rule-import.test.ts` 覆盖加密导出外层；Node 侧用例通过。

## 6. 需要补充的配对实验

二维码导入功能已移除，本节只影响**导出解密**（不影响现有导入路径：明文 JSON / 规则 URL）。如果将来要解导出文件，最有价值的仍是**同一规则的三件套**：

1. 该规则的二维码载荷（`Yealico QR Code: v2:...`）；
2. 该规则的加密导出 JSON；
3. 该规则在 Yealico `Edit` 界面里的字段截图/复制文本（明文）。

有了 1+2+3，才能判断：

- 导出是否用 QR 里的密钥；
- 是否是固定 IV/静态密钥；
- 是否是设备绑定；
- 是否能离线解码。

另外请确认：

- 这个 JSON 是从哪个菜单导出的（导出规则 / 备份 / 分享）？
- 同一个 JSON 在另一台 iOS 设备或另一台 Yealico 中能否导入成功？
- 是否有“导出明文 / 分享 URL”而不是加密 JSON 的选项？

## 7. 建议

在拿到配对样本前，不继续盲试密钥。优先用 [Yealico Edit 取明文](yealico-rule-extraction.md)：它不需要解密，能直接得到可重建规则的字段。加密导出适合作为格式研究样本，不应作为首版导入格式。

## 8. 后续进展：SQLite 已有明文

2026-10-20 进一步确认：macOS 版 Yealico 的 `ComiGa.sqlite` 中 `ZSITE` / `ZSITELISTRULE` / `ZSITEPAGE` 等表直接存储规则明文 JSON。已提取 6 个站点（含禁漫 2.26、阿巴基猫 2.4），因此**规则数据的获取不再依赖导出解密**。加密导出/QR 解密只对“终端用户自动导入”仍有意义。方法与边界见 [yealico-macos-sqlite.md](yealico-macos-sqlite.md)。
